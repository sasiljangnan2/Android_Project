# 브랜치·PR

- main은 검증 가능한 상태를 유지한다.
- feat/recruitment-list, fix/participation-race, docs/firebase-setup처럼 목적별 브랜치를 사용한다.
- 한 PR은 하나의 사용자 행동 또는 독립된 수정 단위로 만든다.
- PR에는 문제와 변경 후 동작, 관련 FR/TC, 검증 결과, 설정/배포 영향, 미검증 범위를 적는다.
- 문서와 실제 코드가 다르면 함께 고친다. 타인의 변경을 덮어쓰지 않는다.
- 사용자 요청 없이 원격 push·merge·deploy를 수행하지 않는다.
