# 기능 명세 v0.1

## 근거와 해석
2026-10-12 요구사항 분석서(8쪽)를 상세 기준으로 사용하고, 2026-10-04 제안서(4쪽)를 목적·사용자 맥락으로 사용한다.
대학 정문·실제 좌표는 미정. 서울시청 인근의 샘플 좌표는 시연에서만 사용한다.
제안서 F3의 강제 퇴장은 분석서 Won’t와 충돌하여 제외한다.
Backpack_Crop는 문서 분류 방식만 참고한다.

## 사용자·범위
대학 주변 1인 가구 학생. 같은 계정이 모집자와 참여자가 된다. 실제 서비스는 인증 후 이용한다.
정문 기준 직선 2km 안의 수령 장소만 등록한다. 현재 위치 또는 정문 기준 500m·1km·2km로 탐색한다.
계정·인증은 FR-01~03의 공통 선행 조건이다. 시연 모드는 개발 미리보기이며 운영 게스트 기능이 아니다.

| ID | 우선순위 | 정상 동작 | 오류·수용 기준 |
| --- | --- | --- | --- |
| FR-01 | Must | 반경 목록·상세, 제품·수량·가격·예상 비용·인원·마감·수령·상태 표시 | 서비스·검색 반경 모두 적용, 위치 실패 5초 후 정문, 빈 목록과 실패 구분 |
| FR-02 | Must | 사진·제품·수량·가격·예상 비용·목표·마감·지도 장소 등록 | 필수 누락·2명 미만·미래 아닌 마감·2km 밖 차단, 모집자 자동 참여 |
| FR-03 | Must | 한 계정 한 자리, 정원 충족 즉시 매칭, 모집 중 참여 취소 | 초과·중복 0건, 모집자 취소 차단, 마감 미충족 취소, 매칭 후 취소 차단 |
| FR-04 | Should | 매칭 참여자 전용 채팅 | 서버가 비참여자·매칭 전 조회·전송 차단 |
| FR-05 | Should | 매칭·취소 알림과 상세 최신 상태 조회 | 현재 푸시는 후속 구현. 알림만으로 상태 확정 금지 |

## 상태 전이
`open → matched`: 참여 요청으로 모집자 포함 인원이 target에 도달한 경우.
`open → cancelled`: 서버 시각이 마감 이상이고 미충족인 경우.
matched/cancelled는 최종 상태. 마감과 같은 시각의 신규 참여는 거부한다.
모집 중 일반 참여자 취소는 open을 유지한다. 모집자 자신의 취소는 금지한다.
동일 계정의 이미 승인된 참여 재시도는 저장된 참여 결과를 반환하며 추가 자리를 만들지 않는다.
매칭 후 협의 취소·수령 일정 변경은 채팅에서 합의하며 앱 상태를 재모집으로 돌리지 않는다.

## 품질 목표
목록·상세·참여 2초, 등록 5초, 채팅 전송 2초. 동일 환경 20회 중 19회 목표 이내.
통신 오류 5초 이내 안내. 결과 미확인 시 최신 상태 재조회 전 참여·취소 재전송을 막는다.
이 수치는 목표이며 아직 성능을 검증하지 않았다. 스케줄러 지연에도 참여 시각 검증은 별도로 수행한다.

## 초기 구현의 추가 결정
- 서버 목표 인원 2~100명, 필수 문자 최대 120자, 양의 정수 원화, 사진 5MB 이하.
- 메시지 1~1000자, 최근 100개, 4초 폴링. 운영 전 페이지네이션·실시간 수신 검토.
- 지도는 flutter_map/OSM으로 선정. 운영용 타일 정책·제공자 확정 필요.
- 삭제·수정 API는 범위를 정한 뒤 별도 설계. 현재는 제공하지 않음.

## 제외
실제 구매·주문·결제·자동 비용 계산·정산·환불·분배·배송 관리, 매칭 전 채팅, AI·가격 추천,
전국 운영·사업자 화면·외부 구매 서비스·운영 게스트·오프라인 목록 저장,
매칭 후 재모집·인원 변경·강제 퇴장 투표. 별점·후기는 Could이나 미구현.
